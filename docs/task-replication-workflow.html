Backrooms Task Replication

Workflow & Blueprint Architecture — System Overview

Architecture Direction
All authoritative task state has migrated from BP_PS_Gameplay (PlayerState) into BP_GS_Gameplay (GameState). Widgets and task items now query GameState directly for replicated task data.

High-Level Flow Summary

  1. Player Interaction — A player walks up to an in-world BP_Task_Item_Base and presses the interact key. The interaction event fires on the owning client.
  2. Local Progress — The task item (or the owning BP_PS_Gameplay) increments local progress and calls IsTaskComplete.
  3. Server RPC — If the task is complete, a Run-on-Server / Reliable event (Server_ReportTaskCompleted) is dispatched from the client-owned PlayerState or PlayerController to the server.
  4. GameMode Validates — On the server, BP_GM_Gameplay receives OnTaskCompleted(TaskID), deduplicates, and writes the result into BP_GS_Gameplay.
  5. GameState Replicates — GloballyCompletedTaskIDs and all task-progress arrays in GameState are replicated to every client via RepNotify.
  6. UI Updates — Each client's WBP_Inventory / HUD observes OnRep_CompletedTaskIDs and refreshes task rows — no more PlayerState cast needed.

Blueprint Roles at a Glance

Blueprint Network Role Responsibility (new architecture)
BP_Task_Item_Base Actor — replicated Detects interaction, calls progress update, fires server RPC on completion
BP_PS_Gameplay PlayerState — replicated per-player Hosts Server_ReportTaskCompleted RPC; local UI progress mirroring only
BP_GM_Gameplay GameMode — server-only Validates completion, deduplicates TaskIDs, writes into GameState, checks win condition
BP_GS_Gameplay ★ GameState — replicated to all Authoritative source for task lists, per-task progress, and globally completed IDs
BP_PC_Gameplay PlayerController — owned by client Optional secondary RPC bridge if task item cannot reach PlayerState directly
WBP_Inventory Widget — local only Casts to GameState (not PlayerState) to build and refresh task rows
WBP_TaskRow Widget — local only Reads progress and completion state from GameState variables
Migration Note
Any existing Blueprint node that does Cast to BP_PS_Gameplay → Get ActiveTasksList (or similar) inside a widget must be updated to Cast to BP_GS_Gameplay → Get ActiveTasksList. See the Widget / UI page for the exact node changes.
