GameState Task Logic

BP_GS_Gameplay  — authoritative replicated task data

Key Change
All shared task state — task lists, per-task progress, and globally completed IDs — has moved from BP_PS_Gameplay (PlayerState) into BP_GS_Gameplay (GameState). PlayerState is now only responsible for the RPC bridge and optional local progress mirroring.

Variables in BP_GS_Gameplay

Variable NameTypeReplicationPurpose
ActiveTasksList Array of BP_Task_Item_Base Ref Replicated All task items currently active in the level. Populated on BeginPlay (server) by querying all placed task actors.
TaskProgressMap Map <Name → Int> RepNotify Current interaction count per TaskID.
TaskGoalMap Map <Name → Int> Replicated Required interactions to complete each task. Set from task-item defaults at runtime.
GloballyCompletedTaskIDs Array of Name RepNotify All TaskIDs confirmed complete by the server. Drives UI completion indicators across all clients.
CompletedTaskCount Integer Replicated Total tasks completed this match. Used for win-condition checks and HUD display.

Before vs. After

❌ Old — PlayerState owns task data

  • ActiveTasksList in BP_PS_Gameplay
  • IncrementTaskProgress on PlayerState
  • IsTaskComplete queries PlayerState
  • Tablet casts to PlayerState
  • Other players never see updates

✅ New — GameState owns task data

  • ActiveTasksList in BP_GS_Gameplay (replicated)
  • UpdateTaskProgress writes to GameState map
  • IsTaskComplete queries GameState
  • Tablet casts to GameState
  • All clients auto-sync via RepNotify

Initialization Flow (Server BeginPlay)

RepNotify — Keeping Clients in Sync

Two variables in BP_GS_Gameplay use RepNotify rather than plain Replicated. This fires a callback on every client when the value changes, allowing the UI to refresh immediately without polling.

UpdateTaskProgress — Server Side

This function runs only on the server and modifies TaskProgressMap in GameState. After updating, it checks whether the task goal has been met and, if so, calls GameMode → OnTaskCompleted. 

// Pseudo-blueprint logic — UpdateTaskProgress (Server / GameState)
// Input: TaskID (Name), Increment (Int, default 1)

Current = TaskProgressMap[TaskID] + Increment
Set TaskProgressMap[TaskID] = Current      // triggers OnRep on clients

Goal = TaskGoalMap[TaskID]
if Current >= Goal:
    if GloballyCompletedTaskIDs does NOT contain TaskID:
        Add TaskID to GloballyCompletedTaskIDs   // triggers OnRep
        CompletedTaskCount++
        GetGameMode() → Cast BP_GM_Gameplay → OnTaskCompleted(TaskID)
Best Practice
Always guard with Has Authority before writing to any replicated variable in GameState. If called from a client context by accident, Unreal will silently drop the write on clients, leading to inconsistent state — use a Switch Has Authority node at the top of any function that modifies GameState.

PlayerState's Remaining Role

BP_PS_Gameplay now serves a narrow purpose:

  • Hosts the Server_ReportTaskCompleted(TaskID) Run-on-Server RPC (clients can call RPCs on their own PlayerState).
  • May hold optional local-only progress mirrors for immediate UI feedback before replication arrives.
  • Does not own ActiveTasksList, TaskProgressMap, or any authoritative task state.
Remove From PlayerState
The following variables should be removed from or deprecated in BP_PS_Gameplay after the migration: ActiveTasksList, IncrementTaskProgress (authoritative version), and any variable that duplicated GameState task data. Keep only the RPC and any local-feedback helpers you intentionally want.
